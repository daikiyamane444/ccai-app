## 判定: 実装可（維持）

## 確認した変更点
v2 の変更は、人間の決定の反映だけ（要求の追加なし）。

- 状態を「実装可」に、関連に D-009（技術構成）を追記。
- Q-P8・Q-P9・Q-U1 の「仮置き／仮決定」を D-011 の決定に置き換え。内容はそれまでと同じ。
  - Q-P8: セッション有効期間は認証基盤の標準のまま。30日上限は公開準備SPECで設定する。
  - Q-P9: 登録時に「登録済み」と分かる動作は公開前まで許容し、公開前に必ず解消する。
  - Q-U1: 「18歳以上」の自己申告チェック。
- 受入基準 AC-1〜AC-18 は変更なし。

## 実装可が維持される理由
- D-009 の技術構成（Next.js、Supabase 東京、Supabase Auth）は、前回レビューで想定した構成と同じ。選定案で確認した制約（cookie の HttpOnly、RLS の権限の取り消し、Docker 前提、メール確認なしの重複登録の応答）は、000a の受入基準・例外の記述に既に織り込まれている。
- 前回の「実装時の既定値」と「軽微な指摘」（AC-4 への登録済みメールのテスト追加の任意提案など）は、そのまま有効。

## 残る注意（変更なし）
- AC-8（ブラウザのスクリプトからトークンを読めない）: Supabase の標準構成では成立しない可能性があり、実装の最初に確認する。サーバー側だけで認証・データアクセスを行い HttpOnly の cookie を付ける構成を試し、成立しなければ止めて戦略担当へ戻す。
