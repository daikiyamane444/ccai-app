**確認して問題がなかった点**
- **(1) 従量課金の経路がない**
  - `ANTHROPIC_API_KEY` を読むコードはない（grep。出てくるのは、渡さないことを確かめるテストと、ビルド検査の禁止語だけ）
  - SDK に渡す環境変数は丸ごと置き換えで、許可した9つのキーだけ（テストで確認。L3 で検出）
  - APIキー方式のアダプタはない
  - 自動テストでは `ANTHROPIC_API_KEY`・`CLAUDE_CODE_OAUTH_TOKEN` を空にしている（`vitest.config.ts`）
- **(2) Agent SDK の安全設定**: `tools: []`・`allowedTools: []`・`mcpServers: {}`・`strictMcpConfig`・`settingSources: []`・`persistSession: false`・`maxTurns: 1`。作業フォルダと設定フォルダは空の一時フォルダで、呼び出しのたびに削除する（テストで確認）。実際に渡す設定のテストが弱い点は M-2
- **(3) 公開環境と成果物**
  - 公開環境（`VERCEL` があるか、`NODE_ENV=production`）では、プラン方式の呼び出しは「設定不足」になる（L2 で検出）。評価コマンドも拒否する
  - 画面・API から LLM の部品を読み込んでいない
  - Agent SDK は開発用の依存だけで、`outputFileTracingExcludes` により公開用の関数に含めない
  - check-build で、ブラウザ向けJSに SDK・`CLAUDE_CODE`・`LLM_MODE` がないこと、サーバー成果物に SDK の実行ファイルがないこと、ダミーのトークン値と `ANTHROPIC_API_KEY` の名前が出ないことを確認
- **(4) 上限・境界・D-012**
  - 1日の上限（L5）、日本時間の境界（L7）、予約と排他ロック（L6）、評価（システム）分を1日の回数に数えないこと、削除しても月次集計が変わらないこと（L8・L9）を、いずれも実 Postgres（アプリ用ロール）でのテストで確認
  - 上限の既定値はなく、未設定・不正ならプラン方式は「設定不足」になる。.env.example に仮置き（30回・3000円）の記載あり
- **(5) 本文を出さない**
  - 利用記録・月次集計に本文の列がない（テストで列名を確認）
  - 目印の文字列を使った4経路のテスト（成功・エラー・タイムアウト・上限超過）は、console と標準出力・エラー出力を捕まえて確かめている（L14 で検出）
  - ログに出すのは結果と種類だけ。SDK の例外は種類に直す
  - 評価結果のファイルには、応答文と評価ケースの入力（架空の文）が入る。これは SPEC の第4章どおり
- **(6) 新しい2表の RLS**
  - 両表とも RLS が有効で、`anon`・`authenticated` の権限をすべて取り消し、ポリシーはない
  - 000a の共通部品（`defineIsolationTests`。追加は十数行）で、他人・連携相手・匿名からの読み書き（WHERE なしを含む）を確認
  - 本人の権限でも SELECT・INSERT・UPDATE・DELETE がすべて 42501 になることを確認
  - 月次集計は、本人・連携相手・匿名のいずれも 42501
  - 書き込みは `privileged/llm-usage.ts`（service_role）だけ
