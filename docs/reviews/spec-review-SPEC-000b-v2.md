## 公式ドキュメントでの確認結果（確認日 2026-10-07。出典は architecture.md 第10章の29〜37）

| 確認点 | 結果 |
| --- | --- |
| TypeScript版の認証（プランのログイン） | ○ 確認。`claude setup-token`（Pro/Max/Team/Enterprise向け、有効期間1年のOAuthトークンを表示。保存はされない）で作ったトークンを環境変数 `CLAUDE_CODE_OAUTH_TOKEN` に設定する。CI・スクリプト向けとして公式に説明されている（出典30）。`/login` のログイン情報（Linuxでは `~/.claude/.credentials.json`）でも動く。注意: `ANTHROPIC_API_KEY` が環境にあると、非対話実行ではAPIキーが優先される（出典30）ため、設定しない |
| ツールの全無効化 | △ 部分確認。`tools`（ツール名の配列またはプリセット）と `disallowedTools`（名前だけ指定するとツールがコンテキストから外れる）がある（出典32）。**`tools: []` で全無効になることを明記した文は取得できなかった（未確認）**。確実にするため、既知の組み込みツール名を `disallowedTools` に並べ、権限モードを `dontAsk`（確認が要る呼び出しはすべて拒否）にする二重の設定を提案する。実装時に、初期メッセージ（`init`）のツール一覧が空であることをテストで確認する |
| 設定ファイル（CLAUDE.md等）を読ませない | ○ `settingSources: []` でユーザー・プロジェクト・ローカルの設定と CLAUDE.md を読まない（出典33）。ただし次は `settingSources` に関係なく読まれる: 管理ポリシー、`~/.claude.json`、自動メモリ（`~/.claude/projects/.../memory/`）、claude.ai のMCPコネクタ。対策: `env` に `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` と `CLAUDE_CONFIG_DIR`（空の一時ディレクトリ）を渡す。`setup-token` のトークンは「モデルへの要求だけ」を行えるため、claude.ai のコネクタも読み込まれない（出典30, 33）。`skills: []` でスキルも無効にできる（出典33） |
| システムプロンプト | ○ `systemPrompt` に文字列を渡せる。省略時は最小のプロンプト（出典32） |
| 1往復だけの実行 | ○ `maxTurns` はツール使用の往復数だけを数える（出典34）。ツールがなければモデルは1回応答して終わる。上限に達すると `error_max_turns` が返る。**`maxTurns: 1` を指定したときの境界の挙動は未確認**（実装時に実測する） |
| 会話記録の保存無効化 | ○ TypeScriptは `persistSession: false` で、ディスクへの保存をしない（出典32, 35）。AC-11 の「無効にする」で満たせる。そのほか、自動メモリ（上記）とテレメトリ（`DISABLE_TELEMETRY`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`。出典36）も止める |
| モデル指定 | ○ `model` に別名または完全なモデル名を渡せる（出典32）。`claude-sonnet-5-5`、`claude-haiku-4-5-20251001` の指定は可能。**契約中のプランでこの2つが選べるかは未確認**（実LLM評価の前に人間が確認） |
| 最大出力トークン | △ `query()` のオプションに専用の項目は見つからなかった。環境変数 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` で上書きできる（出典36。`env` オプションで渡す）。思考（thinking）が有効だと出力が増えるため、`thinking` の設定（既定は適応的）か `CLAUDE_CODE_DISABLE_THINKING` で止める。**SPEC に「最大出力トークンを実行方式へ渡す」ことの受入基準がない**（提案は下の指摘3） |
| タイムアウト | △ `abortController` で中止できる（出典32）。環境変数 `API_TIMEOUT_MS`（既定10分）と `CLAUDE_STREAM_IDLE_TIMEOUT_MS` もある（出典36）。アダプタ側で30秒の `AbortController` を使う設計でよい。起動時間の実測は実装時 |
| 使用量（トークン数・費用）が結果から取れるか | ○ 結果メッセージに `usage`（入力・出力・キャッシュのトークン数）、`modelUsage`、`total_cost_usd` がある。全ての結果（失敗も）に付く（出典34）。`total_cost_usd` は **クライアント側の推定**（`maxBudgetUsd` の説明より。出典32）。SPEC の「単価による推定を正とする」方針と整合する。失敗の途中（クラッシュ時）は0になりうる（出典34）ので「見込みのまま確定」の既定値が役立つ |
| エラーの見え方 | ○ 結果の `subtype`（`error_max_turns`、`error_during_execution` 等）。1回きりの `query()` は、エラー結果を返した後に例外を投げるので、`try/catch` で受ける（出典34）。**プランの利用上限に達したときのエラー種別は取得できなかった（未確認）**。SPEC は「失敗＋エラーの種類で区別、再試行しない」としているので、実装時に実際の応答を見て種別を割り当てる |

## 人間に伝えるべき事実（開発担当が公式で確認した、D-010 の前提との差）

**事実A: 「Agent SDK 用の月次クレジット」は現在停止中**
- 公式サポート記事の冒頭に、「6月15日の更新: 以下の変更を一時停止する。現状は何も変わらず、Claude Agent SDK、`claude -p`、第三者アプリの利用は、引き続き**サブスクリプションの利用上限から消費される**」とある（出典29。年の記載は取得できた本文にはなかったため、年は未確認）。
- 検索で見つかった別の記事（2026-05-13付、出典37）は、クレジット（Pro は月$20）が有効としているが、その後に上の停止の更新が出たものと読める。公式の記事を正とする。
- つまり現状は「別枠のクレジットを使い切ったら止まる」のではなく、**普段使っている Claude（対話・Claude Code）と同じ利用上限を、アプリの呼び出しが消費する**。追加課金（利用クレジット／従量）を有効にしていなければ、上限に達すると止まる（出典29は、クレジット使い切り後は有効なら標準のAPI料金になり、無効なら止まると記載）。
- 影響: ①追加費用は出ないが、②**この開発ハーネス自体（AIエージェントが動く作業）と利用上限を分け合う**ため、評価を多く流すと開発作業が止まりうる、③クレジットの金額は確かめようがなく、SPEC の「消費の目安（API定価換算で3,000円相当）」はアプリ内の自己管理の数字に過ぎない。D-010 の趣旨（追加課金なし）はそのまま成り立つ。

**事実B: 第三者への提供は公式に許可されていない**
- 公式ドキュメントは「事前の承認がない限り、第三者の開発者は、Claude Agent SDK で作ったものを含め、自分の製品で claude.ai ログインやそのレート制限を提供することを認めない。APIキーの認証を使う」としている（出典31, 38）。
- 自分の開発・評価に使うことは範囲内と読めるが、**パートナーなど他人が使う段階（Q-H12）は、この方式では許可されない可能性が高い**。Q-H12 の「APIキーへ切替え」を前提に進めるのが安全。切替えは SPEC の方針どおりアダプタ追加で済む。

**事実C: 個人向けプランの学習利用の条件（D-011「学習不使用は必須」）**
- 個人向けプラン（Free/Pro/Max）の会話・コーディング履歴は、「モデル改善への協力」を許可した場合、および安全のために検出された場合は学習に使われうる（出典39）。API（商用）の「既定で学習に使わない」（出典1）とは条件が違う。
- Agent SDK の公式ドキュメントは「商用規約に従う」と書くが（出典31）、プランの認証で動かす場合に個人向けの規約が適用されるのかは**未確認**。
- 対処: Q-H11(2) のとおり、人間がプランの設定で「モデル改善への協力」をオフにする。実利用者の本文を送る SPEC-001 より前に、適用規約を確定する（SPEC に既にある）。保持期間（オフ時）は今回確認できず未確認。

## 観点別の確認

1. **受入基準のテスト可能性**: 良好。AC-11 は、アダプタが SDK に渡す設定を検証する自動テスト（SDK部分はモック）で確かめられる。検証項目（案）: ツール全無効、`settingSources: []`、`systemPrompt` がプロンプトファイル由来、`maxTurns`、`persistSession: false`、`env` に自動メモリ無効・設定ディレクトリの隔離・出力トークン上限、APIキー環境変数が渡っていないこと。
2. **未定義の挙動**: 重大なものはない。下の指摘を参照。
3. **既決・選定との矛盾**: D-009〜D-012 と整合。事実A・B・C は決定の「前提の更新」であり、SPEC の矛盾ではない。
4. **規模**: 受入基準17件。000a 合格後の1サイクルとして適切。
5. **非公開性**: 本文をログ・利用記録・月次集計に出さない（AC-10）、プラン方式のアダプタがツールなし・設定ファイルなしで動く（AC-11）ため、サーバー上のファイルに利用者の入力が触れる経路は閉じている。残る確認は、会話記録が手元に残らないこと（AC-11 の実LLM後の確認）。

## 指摘（判定に影響しない。戦略担当が v3 で拾ってよい）

1. **文言の修正（必ず直してほしい）**: SPEC-000b の第2章・第6章・第7章・第9章の「クレジット枠」「クレジットを使い切ったら」を、「プランの利用上限」に直す。事実Aのとおり、別枠のクレジットは現在ない。decisions D-010 の文言「プラン付属クレジット」も、人間が事実Aを確認したうえで必要なら記録を補足する（decisions.md は戦略担当・人間の管轄）。
2. **Q-H11 の追加確認**: 「追加課金（利用クレジット）の無効」に加え、「開発ハーネス自体と利用上限を共有する」ことを人間が了承すること。評価は1回あたり件数が少ないので影響は小さいと見込むが、プランの種類（Pro/Max）で上限の大きさが違う。
3. **最大出力トークンの受入基準が欠けている**: 第6章の「1回あたりの最大出力トークン数（仮置き800）」を実行方式へ渡していることを確かめる基準がない。提案: AC-11 に「最大出力トークンの上限が実行方式に渡されている」を足す（SDKの専用オプションがなく、環境変数経由になるため、渡し忘れを防ぐ意味がある）。
4. **事実Bの記録**: Q-H12 の欄に「プラン方式は第三者の利用に使えない（公式ドキュメント）。APIキー方式を前提にする」を追記すると、後で迷わない。
5. **SDKの前提**: TypeScript版 Agent SDK は、ネイティブの Claude Code バイナリを同梱して子プロセスとして動かす（出典38）。ローカル実行には問題ないが、公開先のホスティング選定（Q-H8）では、子プロセスを動かせる環境が要る点を覚えておく（Vercel のサーバーレス関数で動くかは未確認。ただし第三者提供の可否（事実B）からAPIキー方式に切り替える前提なので、公開時は無関係になる見込み）。
6. 実装時の既定値（開発側で置く）: 認証は `CLAUDE_CODE_OAUTH_TOKEN` 方式を第一とし、`ANTHROPIC_API_KEY` が環境にあればプラン方式のアダプタは起動を拒否する（意図しない従量課金の防止）。SDK に渡す `env` は必要な変数だけを明示する。
