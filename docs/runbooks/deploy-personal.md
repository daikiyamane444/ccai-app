# 個人用公開の作業手順書（SPEC-000c）

この手順書は、**あなた（人間）がブラウザだけで**、CCAI（仮称）を自分専用のURLで使えるようにするためのものです。ターミナル（黒い画面でのコマンド入力）は使いません。

- 作成: 開発担当（2026-10-07）。画面の名前・ボタンの名前は、各サービスの公式ドキュメントで確かめたものです。**確かめられなかったものは「（未確認）」と書いてあります**。画面が違って見えたら、止めて問い合わせ担当に連絡してください。
- 使うサービス: GitHub（コードの置き場所）、Supabase（ログインとデータ。東京）、Vercel（アプリを動かす場所。東京）。**すべて無料のプランのまま**使います。

---

## 0. はじめに（必ず読む）

### 0-1. 所要時間と必要なもの
- 所要時間の目安: 合計 2〜3時間。途中で中断できます（各所の「チェックポイント」で区切れます）。
- 必要なもの:
  - PC（Chrome、Safari、Edge など）。確認のために iPhone も使います
  - あなた本人のメールアドレス（登録に使う。アプリの登録は**このアドレスだけ**に限定します）
  - パスワード管理の場所（ブラウザやOSのパスワード保存機能、1Passwordなど）。**あとで貼り付けるパスワードをここに保存します**

### 0-2. 費用は0円です（前提）
- GitHub は Free、Supabase は Free、Vercel は Hobby（無料。個人・非商用向け）のまま使います。
- **次のどれかが起きたら、そこで止めて、問い合わせ担当に連絡してください（先に進まない）。**
  1. クレジットカードの登録、有料プランへの切り替え、支払い方法の入力を求められた
  2. 「Pro」「Upgrade」「Billing」などの課金の画面に進まないと設定できない
  3. Supabase の使用量の表示、または GitHub Actions の利用時間が、無料枠の50%を超えている。見る場所（画面名は未確認。見つからなければ「Usage」「Billing」を探す）:
     - Supabase: https://supabase.com/dashboard → 左下の組織 → **Usage**（使用量）。各項目の表示が「Included」（含まれる量）の50%を超えていないか
     - GitHub Actions: https://github.com/settings/billing → **Usage**（または Billing and plans）→ Actions の分数。月2,000分の50%＝1,000分が目安（long ジョブは1回で約70分）
     - Vercel: プロジェクトではなく Vercel のトップ → **Usage**（無料枠に対する割合）
  4. Supabase で「無料プロジェクトの数が上限」と言われて新しく作れない
  5. 規約の確認で、個人の検証用途でも無料プランが使えないと読める記述を見つけた

### 0-3. 秘密情報の扱い（いちばん大事です）
**秘密情報**とは、次のものです。
- Supabase の「公開用キー（anon）」と「管理用キー（service_role）」
- データベースのパスワードと、それを含む接続の文字列
- アプリ用ロール（`ccai_app`）のパスワード
- あなた自身のアカウントのパスワード

**ルール**
- **チャット（Claude を含む）、メール、メモアプリ、スクリーンショット、GitHub の Issue やファイルに、貼らない・写さない。**
- 貼ってよい場所は次の3つだけです。
  1. Vercel の「Environment Variables」
  2. GitHub の「Actions secrets」
  3. あなたのパスワード管理の場所
- 問い合わせ担当（AI）に伝えるのは、「手順が終わった」「OK／NG」「エラーの文言」だけです。エラーの文言に秘密が含まれていそうなときは、その部分を伏せてください。
- スクリーンショットで確認を求める手順はありません。
- **もし誤って貼ってしまったら、慌てずに「14. 運用メモ」の「秘密を漏らしたかもしれないとき」に進んで、そのキーやパスワードを作り直してください。**

## 手順3. Supabase の設定

**目的**: アプリが動く設定にし、使わない入口を閉じる。

3-1. メール確認をオフにする
- 開くURL: Supabase ダッシュボード → プロジェクト `ccai` → 左のメニュー **Authentication**
- 選ぶもの: **Sign In / Providers**（または **Providers**）→ **Email** を開く（画面名は未確認。見つからなければ「Authentication」の中を探す）
- 設定:
  - **Confirm email**（「初回ログイン前にメール確認が必要」）: **オフ**にする
  - **Enable Email provider** / Email は**オンのまま**
- 押すボタン: **Save**
- 期待: 保存の表示が出る。もう一度開いて、Confirm email がオフのままになっている。
- 理由: 000c ではメールの送信をしないため。登録した直後にログインできる状態にする。

3-2. 新規登録の設定（変えない確認）
- 場所: **Authentication** → **Sign In / Providers**（または **Settings**）の中の **Allow new users to sign up**
- 設定: **オンのまま**（アプリが登録するために必要。限定はアプリ側の許可リストで行う）。

3-3. Data API（REST／GraphQL）を無効にする
- 場所: 左のメニュー **Integrations**（または **Project Settings**）→ **Data API**（画面名の候補。公式ドキュメントでは「Data API integration overview」）
- 設定: **Enable Data API** を**オフ**にする。保存する。
- 見つからない／オフにできないとき: **Project Settings → API** などにある **Exposed schemas**（公開するスキーマ）から `public` を外す。それもできなければ止めて連絡（結合テストが外から直接アクセスできないことを確かめるので、後で分かります）。
- 理由: アプリは Supabase の直接の入口を使わない。使わない入口は閉じておく。

3-3b. リフレッシュトークンの設定（確認するだけ。変えない）
- 目的: ログイン状態を続けるための「更新用の合い言葉」（リフレッシュトークン）が漏れたとき、使い回されないようにする仕組みが有効になっていることを確かめる。
- 場所: 左のメニュー **Authentication** → **Sessions**（または **Settings** の中の **Refresh Tokens**、**Advanced Settings**。画面名は未確認。見つからなければ「refresh token」と書かれた設定を探す）
- 確かめること:
  - **Detect and revoke potentially compromised refresh tokens**（漏えいの疑いがあるリフレッシュトークンを検知して失効させる）: **オン**（既定はオン）
  - **Refresh token reuse interval**（再利用の猶予）: **10**（秒。既定）。**変えない**
- オフになっていたら: オンにして **Save**。
- 見つからないとき: 「見つからなかった」と問い合わせ担当に伝える（結合テスト AC-9 が、仕組みが効いているかを確かめます）。
- 補足: Supabase の仕様では、「いま使っている更新用の合い言葉の、1つ前のもの」を使うと、いまのものが返ってきます（通信の途切れに備えた仕様。公式ドキュメント「Sessions」）。2つ以上前のものを使うと、漏えいの疑いとして、そのログイン状態全体が失効します。

3-4. 接続先の情報を確認する（まだ貼らない）
- 場所: **Project Settings** → **API**（または **API Keys**）
- 見るもの: **Project URL**（`https://xxxxxxxx.supabase.co` の形）、**anon**（公開用）キー、**service_role**（管理用）キー（画面が「publishable」「secret」と呼ぶ場合は、publishable が公開用、secret が管理用。未確認）
- やること: **このあと手順8・10で貼り付けます。今はコピーしない。** service_role（secret）キーは、画面の「Reveal」で見せるのは貼り付けの直前だけにする。
- 秘密情報: キーは秘密です。画面を写さない。

**チェックポイント3**: Confirm email がオフ、Data API がオフ（または public を公開していない）、リフレッシュトークンの検知がオン。

## 手順5. データベースの準備（SQLの実行）

**目的**: データを入れる表と、アプリ用のロール（接続用の専用ユーザー）を作る。

5-1. 1つめのSQL（表と保護の設定）
- 開くURL: `https://github.com/あなたのユーザー名/ccai-app/blob/main/app/supabase/migrations/20261007000001_foundation.sql`
- やること:
  1. ファイルの画面の右上にある **Copy raw file**（コピーのアイコン）を押す
  2. Supabase ダッシュボード → 左のメニュー **SQL Editor** → **New query**（新しいクエリ）
  3. 貼り付ける（Ctrl+V。Mac は Cmd+V）
  4. **Run**（実行）を押す
- 期待: 画面の下に **Success. No rows returned**（成功。返す行なし）と出る。
- 警告が出たら: 「破壊的な操作」「RLS」についての確認が出たら、内容が「表を作る」だけなら **Run this query**（実行する）でよい。
- エラーが出たとき: エラーの文言（秘密を含まない）だけを問い合わせ担当に伝える。

5-2. 2つめのSQL（アプリ用ロール）
- 開くURL: `https://github.com/あなたのユーザー名/ccai-app/blob/main/app/supabase/migrations/20261008000001_app_role.sql`
- やること: 5-1 と同じ（**New query** で新しい画面を開き、貼り付けて **Run**）。順番は **1つめ → 2つめ**。
- 期待: **Success. No rows returned**
- **止める条件**: `permission denied to grant role` のようなエラーが出たら、**ここで止めて問い合わせ担当に連絡**。最小権限のロールが使えない可能性があり、代わりの方法を人間が決める必要があります（勝手に進めない）。

5-3. 確認
- 左のメニュー **Table Editor** を開く。
- 期待: `profiles`、`pairs`、`pair_members` の3つの表がある。それぞれに **RLS enabled**（RLS有効）の表示がある。
- さらに **SQL Editor** → **New query** に次を貼って **Run**:
  ```sql
  select rolname, rolsuper, rolbypassrls, rolcanlogin from pg_roles where rolname = 'ccai_app';
  ```
- 期待: 1行が出る。`rolsuper` が **false**、`rolbypassrls` が **false**、`rolcanlogin` が **true**。

**チェックポイント5**: 表が3つあり、ロール `ccai_app` ができている。

## 手順6. アプリ用ロールのパスワード

**目的**: アプリがデータベースに入るためのパスワードを作る。**画面に1回だけ表示されるので、必ず保存する。**

6-1. パスワードを作る
- 開くURL: `https://github.com/あなたのユーザー名/ccai-app/blob/main/app/supabase/manual/set-app-role-password.sql`
- やること: 5-1 と同じ手順で、SQL Editor の **New query** に貼り付けて **Run**。
- 期待: 画面の下の結果の表に、1つのセルがあり、64文字ほどの英数字（`ccai_app_password__copy_this_once` という列名）が出る。
- やること: そのセルの文字列を**コピーして、パスワード管理の場所に保存**する（名前: 「ccai_app パスワード」）。**チャット・メモ・スクリーンショットには貼らない。**
- うまくいかないとき（結果が表示されない／エラー）: 止めて問い合わせ担当に連絡（代わりの手順を案内します）。
- もう一度実行すると新しいパスワードに変わり、古いものは使えなくなる。

6-2. 接続先のホスト名を確認する
- 場所: Supabase ダッシュボードの上部の **Connect**（接続）ボタン
- 選ぶもの: **Transaction pooler**（トランザクションプーラー）
- 見るもの: 画面に出る接続情報のうち **Host**（ホスト）。`aws-0-ap-northeast-1.pooler.supabase.com` のような形（`.pooler.supabase.com` で終わる）。
  - 接続の文字列（`postgresql://…`）しか出ないときは、`@` の後ろから `:6543` の前までがホスト名。
  - **文字列の `[YOUR-PASSWORD]` の部分には触らない。** ここには何も入力しない。
- やること: ホスト名だけをコピーして、パスワード管理の場所に「DB_HOST（秘密ではないがメモ）」として保存する（あとで手順8・10で貼る）。
- 期待: ホスト名が `.pooler.supabase.com` で終わっている。

**チェックポイント6**: パスワード管理の場所に「ccai_app パスワード」と「DB_HOST」がある。

| --- | --- |
| `SUPABASE_URL` | 手順3-4の **Project URL**（`https://xxxxxxxx.supabase.co`） |
| `SUPABASE_ANON_KEY` | 手順3-4の **anon**（公開用）キー |
| `SUPABASE_SERVICE_ROLE_KEY` | 手順3-4の **service_role**（管理用）キー。**最も重要な秘密** |
| `DB_HOST` | 手順6-2で保存したホスト名 |
| `DB_PASSWORD` | 手順6-1で保存した「ccai_app パスワード」 |
| `SIGNUP_ALLOWED_EMAILS` | **あなた本人のメールアドレス**（1つだけ。複数にする場合はカンマで区切る。大文字小文字は問わない） |

- 作らないもの: `DATABASE_URL`（組み立て済みの接続の文字列。人間が組み立てなくて済むよう、`DB_HOST` と `DB_PASSWORD` から自動で作られます）、`DB_USER`・`DB_PORT`・`DB_NAME`（既定値でよい）。
- 入力のしかた: Key の欄に名前、Value の欄にコピーした値を貼り、**Add**（追加）を押す。6個分を繰り返す。
- 貼り付けたあと: 画面を写さない。値の末尾に空白や改行が入っていないか確認する。
- 期待: 6個の変数が一覧に並ぶ（値は伏せ字）。

**チェックポイント8**: 6個の環境変数がある。

### 手順9-b. デプロイ直後に、すぐ本人が登録する（S-1。推奨）

**目的**: 登録の入口を、本人の登録が済んだらすぐ閉じる。理由: 本人が登録するまで、そのメールアドレスは「まだ誰も使っていない」ので、URL を知っている人が先に同じアドレスで登録しようとする余地がわずかにあります（個人用URLは広めなければ、まず起きません）。

- **手順9のデプロイが Ready になったら、手順11-1（新規登録）を、すぐ行ってください**（11 の他の確認はあとでよい）。
- 登録できたら、次の「登録を閉じる（任意だが推奨）」を行う。
  1. Vercel のプロジェクト → **Settings** → **Environment Variables** → `SIGNUP_ALLOWED_EMAILS` の **値を空にして保存**（または変数を削除）。
  2. **Deployments** → 最新の行の **…** → **Redeploy**。Ready になるまで待つ。
- 期待: 登録ずみのあなたは、これまでどおりログインできる。ほかのメールアドレスでの新規登録は、すべて **現在、新規登録を受け付けていません** になる（許可リストが空のときは、登録を全部断る仕様）。
- 登録を再び開けたいとき（別のアドレスを使うなど）: `SIGNUP_ALLOWED_EMAILS` にアドレスを入れ直して Redeploy。
- 注意: 結合テストの **AC-18**（一覧にないアドレスの拒否）は、一覧が空でも、設定されていても、同じ結果（拒否）になります。**手順10の `CI_LEAK_PROBE` を使う場合**（一覧の中身の漏れ検査）は、一覧を空にする**前**に結合テストを1回流すか、このアドレスを入れて検査してください（空にしたあとは検査の意味がなくなりますが、失敗にはなりません）。

## 手順11. PC での確認

**目的**: 自分専用のURLで、登録・ログアウト・ログイン・戻るボタンを確かめる。使うブラウザは Chrome を勧めます。

11-1. 新規登録
- 開くURL: 手順9で控えた個人用URL（開くと自動でログイン画面になる）
- 押すもの: **新規登録はこちら**
- 入力: メールアドレス（**手順8の `SIGNUP_ALLOWED_EMAILS` に入れたもの**）、パスワード（8文字以上72文字以内。パスワード管理の場所で生成して保存）、表示名（任意）、**18歳以上であることのチェック**を入れる
- 押すボタン: 登録のボタン
- 期待: ホーム画面になり、表示名（またはメール）が出る。
- 別のメールアドレスで試すと **現在、新規登録を受け付けていません** と出ること（確認したい場合）。

11-2. ログアウトとログイン
- ホームの **ログアウト** を押す → ログイン画面になる。
- 同じメールとパスワードでログイン → ホームに戻る。

11-3. 戻るボタン
- ログアウトした直後に、ブラウザの **戻る** ボタンを押す。
- 期待: ホームの内容（表示名など）が一瞬も見えず、ログイン画面のままか、ログイン画面に移る（AC-21）。

11-4. cookie が読めないことの確認（開発者ツール）
- ログインした状態で、キーボードで次を押す。
  - Windows／Linux の Chrome: **Ctrl + Shift + J**
  - Mac の Chrome: **Command + Option + J**
- 開いた画面の **Console** タブの下の入力欄に、次の文字だけを打って **Enter**:
  ```
  document.cookie
  ```
  （画面に「貼り付けないで」という注意が出る場合があります。**この1行だけ**を自分で打つのは安全です。ほかの人から渡された文字列は貼らないでください。）
- 期待: `''`（空）が返る、または `ccai_session` という名前が**含まれない**（AC-16）。`ccai_session` が見えたら **NG**。
- 閉じるときは、同じキーをもう一度押す。

11-5. PC の Chrome でインストールの案内（AC-20。出なくても NG ではありません）
- ログイン画面かホームを開いた状態で、アドレスバーの右端を見る。
- 期待: **インストール**（パソコン画面と矢印のようなアイコン）が出る。押すと「CCAI（仮称）をインストール」の確認が出る（インストールまでしなくてよい。押さずに閉じてよい）。
- 出ないとき: 「出なかった」とだけ、チェックリストの AC-20 に書く（判定は品質担当）。

## 手順12. iPhone での確認

**目的**: iPhone の Safari で使えるか、ホーム画面に追加できるかを確かめる。

12-1. Safari で開く
- iPhone の **Safari** で、個人用URLを開く（URLはメッセージに貼らず、パスワード管理の場所やメモから入力・コピーしてください。秘密ではありませんが、共有しない）。
- 確認:
  - ログイン・新規登録・ホームの画面で、**横にスクロールしない**（AC-19）
  - 入力欄をタップしても、**画面が勝手に拡大されない**
  - ボタンと「新規登録はこちら」「ログインはこちら」が押しやすい
- ログインする。

12-2. ホーム画面に追加
- Safari の下（または上）の **共有ボタン**（四角から矢印が出ているアイコン）→ **ホーム画面に追加** → 名前が **CCAI（仮称）** になっていることを確認 → **追加**（AC-20）。

- 期待: アドレスバーのない、全画面表示で開く。ログイン済みならホームが出る。

12-3. 戻る・機内モード（AC-21、AC-22）
- ホーム画面のアイコンから起動した状態でログアウトし、画面左端からの右スワイプ（戻る）をしても、ホームの内容が見えない。

12-4. PC でのログアウトの影響（AC-23）
- iPhone でログインしたまま、PC でログアウトする。
- iPhone で画面を操作（再読み込み）する。
- 期待: iPhone もログイン画面に戻る（全端末からログアウトされる仕様）。

### 結合テストが使えないときの代わり（人間が確かめる）
Actions が動かせない場合は、次を人間が確かめます（問い合わせ担当の指示があったときだけ）。
1. Supabase の **SQL Editor** で次を実行し、結果の行が次のとおりであること（AC-10 の権限）:
   ```sql
   select grantee, table_name, privilege_type
   from information_schema.role_table_grants
   where table_schema = 'public' and grantee in ('anon', 'authenticated')
   order by grantee, table_name, privilege_type;
   ```
   期待: `authenticated` が `pair_members: SELECT`、`pairs: SELECT`、`profiles: INSERT, SELECT`。`anon` は行なし。（`profiles` の `display_name` 列の更新権限は、この一覧には出ない。）
2. 手順11〜12 を行い、**ログインしたまま1時間以上待ってからログアウト**する（AC-12）。

## 手順14. 運用メモ（読むだけ）

### Supabase の Free プロジェクトは、使わないと止まる
- 1週間ほど十分な利用がないと、自動で一時停止します。そのとき、アプリの画面は「通信できませんでした。電波の良い場所でもう一度お試しください」になります。
- **再開の方法**: https://supabase.com/dashboard → 組織 → プロジェクト `ccai` → **Resume project**（プロジェクトを再開）→ 確認。データと設定はそのまま戻ります（復元できる期間は1年）。数分かかります。
- 結合テストも、止まっている間は失敗します。

### PC でログアウトすると、iPhone もログアウトされます
- 仕様です（全端末からのログアウト。端末を他人に見られたときに、別の端末から全部を切れるようにするため）。

### 個人用URLは、他人に教えないでください
- 登録は本人のメールアドレスだけに限っていますが、URL を広めないことが最初の守りです。検索エンジンに載らない設定も入れてあります。

### 秘密を漏らしたかもしれないとき（チャットなどに貼ってしまった場合も）
慌てず、次のうち、**漏らしたものだけ**を作り直します。作り直したら、古いものは使えなくなります。

1. **ccai_app のパスワード**: 手順6-1をもう一度実行する（新しいパスワードができる）→ 新しい値を、パスワード管理の場所、Vercel の `DB_PASSWORD`、GitHub の `DB_PASSWORD` に上書きする → Vercel で **Redeploy**。
2. **Supabase のキー（anon／service_role）**: **Project Settings → API**（または **API Keys**）で、キーを作り直す（**Regenerate**／ローテーション。画面の名前は未確認）→ 新しい値を Vercel と GitHub の該当の変数に上書き → Vercel で **Redeploy**。
3. **Supabase の Database Password（postgres）**: **Project Settings → Database** の **Reset database password** で作り直す。アプリは使っていないので、ほかへの上書きは不要です。
4. **あなたのアカウントのパスワード**: アプリでは、いまはパスワードの再設定機能がありません。問い合わせ担当に連絡してください。
5. Vercel の環境変数を貼り直したときは、必ず **Redeploy**（設定は再デプロイで反映されます）。

### 結合テストのあとの確認
- Supabase → **Authentication** → **Users** に、`ccai-ci+` で始まり `@example.invalid` で終わるアドレスが残っていないこと。残っていたら、問い合わせ担当に連絡し、下の「テスト用ユーザーを手で消す」を行う（次の結合テストの開始時にも、自動で消えます）。

### テスト用ユーザーを手で消す（結合テストの取り残し）
2026-10-08 の初回の結合テスト（実行番号 37705052038）では、テストの不具合で、テスト用ユーザーが **最大5件** 残った可能性があります（不具合は修正済み）。次の手順で消してください。修正後の結合テストを1回流すと自動でも消えますが、先に手で消してかまいません。

1. 開くURL: https://supabase.com/dashboard → プロジェクト `ccai` → 左のメニュー **Authentication** → **Users**
2. 上の検索欄（**Search for a user**。画面名は未確認）に `ccai-ci` と入力する。
3. 一覧に出たアドレスを、1件ずつ確かめる。**消してよいのは、次の3つをすべて満たすものだけ**:
   - `ccai-ci+` で始まる
   - `@example.invalid` で終わる
   - 例: `ccai-ci+37705052038-setlocal-a@example.invalid`、`…-rest-a@…`、`…-rest-b@…`、`…-del-c@…`、`…-site-login@…`
   - **あなた本人のアドレスは絶対に消さない**（本人のアドレスは `@example.invalid` で終わりません）
4. 消す行の右端の **…**（またはチェックを入れて上部のメニュー）→ **Delete user**（ユーザーを削除）→ 確認の画面で **Delete** を押す。
5. 全部消したら、検索欄に `ccai-ci` と入れて、0件になったことを確かめる。検索欄を空にして、**あなた本人のアカウントが残っている**ことも確かめる。
- 補足: ユーザーを消すと、そのユーザーのプロフィールなどのデータも、自動で消えます（データベースの設定）。
- 迷ったら: 消さずに、問い合わせ担当に「何件あったか」だけを伝えてください（アドレスそのものは貼らなくてよい）。

## 付録. 用語
- **リポジトリ**: コードの置き場所。**Private** は非公開。
- **デプロイ**: アプリを公開すること。**Redeploy** はやり直し。
- **環境変数**: アプリに渡す設定の値。秘密情報はここに入れる。
- **RLS**: 他人のデータを読めなくするデータベースの仕組み。
- **ロール**: データベースの「利用者の種類」。`ccai_app` はアプリ専用の最小限の権限のロール。
